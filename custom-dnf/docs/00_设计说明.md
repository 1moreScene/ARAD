# custom-dnf 第一步 · 设计说明

> 范围：**可玩场景（官方真实素材）+ 默认鬼剑士 + 与官方一致的移动/奔跑/跳跃逻辑 + 官方默认键位**。
> 目标不是"做一个游戏"，而是把「坐标系 / 层次 / 时间 / 输入 / 弹道」这些**骨架**做成官方的形状，
> 并且**画面、地图、角色全部直接用官方文件**（`.map` / `.til` / `.NPK` / `.img` / `.ani` / `.chr`），
> 不自制替代素材。

---

## 1. 为什么是零依赖

* 官方客户端是 D3D8 + DirectInput8 的 2006 年技术栈；本步的画面是**纯 2D 精灵合成**
  （官方素材本身就是预渲染精灵 + 画布偏移），用不上着色器，**软件光栅 + GDI 呈现**完全够用，而且：
  * 离线可构建（不依赖 crates.io 网络）；
  * 逐像素可断言（无头 PNG 导出 → 确定性验证）；
  * 不会被 wgpu/winapi 版本漂移拖累。
* 唯一的外部依赖是系统 DLL：`user32`（窗口/输入）、`gdi32`（呈现）、`kernel32`（计时），
  全部手写 `#[link] extern "system"` 声明。

## 2. 坐标系：2.5D（照抄官方语义）

| 轴 | 含义 | 来源 |
|---|---|---|
| `x` | 水平轴 | 官方 `.map` 的对象锚点 x |
| `y` | **纵深轴**（进/出屏幕） | 官方 `.map` 的对象锚点 y；**直接就是屏幕 y**（`docs/90` 会话 13 第 5 条） |
| `z` | 跳跃的**屏幕上移量** | 不影响 `y`；只影响绘制偏移与影子大小 |

* **方向键语义**：`←/→` 动 `x`；`↑/↓` 动 `y`（纵深）。
* **画家排序**：按 `y` 从小到大绘制 ⇒ `y` 大的角色挡住 `y` 小的。
* **房间**：直接读官方 `map/lorien/104.map` —— 5 条瓦片带 × 224px = **1120px** 宽，
  左右门外沿 `x = 16 / 1104`；纵深由每条 `.til` 的 `[pass type]` 网格给出
  （14 列 × 30 行 × 16px，`0` = 可走、`2` = 阻挡；洛兰森林实测可走带 `y ≈ 224..463`）。
* **出生点** = `[pathgate pos]` 里最靠左的门（官方就是从左门进房），
  相机恒夹在 `[0, 房间宽-640]` 内，所以视口永远落在房间内、不露黑边。

## 3. 时间与状态门

重制默认60Hz定步，动画使用官方毫秒DELAY；官方实际控制器接收毫秒dt。
普通跳跃按准备、飞行、落地三个阶段推进，准备到帧1才发射，vz到顶点设帧8，碰地设帧15。
落地末帧50ms播完回自由态；锁定由动画门决定，没有额外固定帧数冷却。

## 4. 移动与奔跑

- 输入按最近仍有效记录决定方向，两轴独立，后按优先、松开回落。
- 步行参数x143/119、y114/95；奔跑x286/238、y136/114。
- 参数乘移速千分比，任一轴无输入选择直向档；斜向不归一化。
- 左左/右右逻辑命令后缀窗口500ms，其他逻辑按键可打断序列。
- 命令候选与角色有效状态11分开。反向或两轴动作方向都无效会退出奔跑。
- 官方动作方向来自实际vx/vy的±5阈值分类，原始按键方向是另一接口。
- 官方控制器保存浮点位置，使用平均速度积分；432F40四舍五入输出整数坐标。
- 停步保留位置小数，房间夹取后重新同步位置。
- 基础850角色的走/跑动画85%，站立和普通跳跃100%。

左右重叠时的持续奔跑抑制是已有实测的本地归并；官方请求、仲裁、回执时序尚未逐帧复刻。
本次角色核心修正不等于复刻整个联网状态机。证据与限制统一见[02_移动与跳跃取证.md](02_移动与跳跃取证.md)。

## 5. 跳跃

普通跳跃x继承起跳时档位，y参数整数除2再乘移速：步行起跳57/47，奔跑起跳68/57。
准备和落地锁定平面位移与转向；飞行可调整两轴和朝向；落地恢复自由态，不自动恢复跑步开关。

`v0 = 4000*jump_power / ((integer_divide(100*weight,jump_speed)-10000)*0.0121+2100)`。
普通无装备修正时`g = integer_divide(1500*jump_speed,100)`。
基础鬼剑士430/68000/95：v0≈604.5495、g=1425、理想最高点≈128.24px、纯飞行≈848.49ms。
完整动作还包含准备100ms和落地50ms。账号属性、装备、采样步长与碰撞会影响实测。

受控/技能跳跃是另一包标志分支，x286/286、y0、固定重力且转向受限，当前普通操作接口未接入该技能分支。

## 6. 渲染（官方真实素材）

* 逻辑分辨率 **640×480**（官方内部渲染分辨率）。
* 每一帧按官方层次顺序拼出来（`crates/dnf-app/src/room.rs`）：

  ```
  远景层(distantback, 视差 56%) → 中景层(middleback, 视差 90%) → 瓦片条(世界锁定)
    → closeback 物件 → bottom 物件 → normal 物件(按锚点 y 排序) → 角色 → close 物件(前景)
  ```

  * 远景/中景：`.map` 的 `[background animation]` → `.ani` → `Map\01far1.img`（640×295），
    横向按 640 取模平铺，位移 = `camera_x × 视差率 / 100`。
  * 瓦片条：`.til` 的 `[IMAGE]` → `Map\01tile00.img`（画布 224×480，美术贴画布 `(0, 277)`），
    屏幕 x = `条号 × 224 - camera_x`。
  * 物件：`.map` 的 `[animation]` → `.ani` → `.img`，锚点 = 官方坐标，
    绘制偏移 = `[IMAGE POS] + 帧在画布内的 (x, y)`。
* 角色是**官方分层合成**，绘制顺序 = 官方 `.equ` 的 **`[LAYER]` 升序**（身体层 0）：
  身体层读 `character/swordman/animation/<动作>.ani`（权威帧序 + `[IMAGE POS]`）；
  每个时装槽按 `[equipment type]` + `[variation]` 在官方表里定位装备
  （`equipment/character/swordman/avatar/<槽>/<物品>.equ`），取它的 `[LAYER]` 与部件目录
  `equipment/.../avatar/<槽>/<槽>_<字母>/<动作>.ani` 里的**路径模板** `sm_coat%02d%02da.img`，
  用 `[variation]` 填号。
  官方层值（剑士）：`face_b 100` / `coat_d 500` / `neck_d 600` / `belt_b 1100` / `shoes_b 1200` /
  `pants_b 1300` / `shoes_a 1400` / `pants_a 1500` / `belt_a 1700` / `neck_a 1800` /
  `coat_a 1900` / `hair_a 2000` / `cap_a 2100` / `neck_c 2200` / `cap_c 2500`（负数 = 画在身体之前）。
  身体层 = 0 是**区间推断**（负数层＝身体之前、最小正数层＝99/100 ⇒ 身体 ∈ `(-50,99)`）。
  同一槽的**兄弟部件一起画**（`.equ` 只点一个目录，但裤子真正的美术在 `pants_b`）。
  官方图集里还有"什么都不画"的**空帧**（1x1 全透明、画布 `(500,0)`），并大量使用
  `tag 0x11` **别名帧**（`sm_pants0000a.img` 188 帧里 182 帧是别名）——两者都已正确解析。
* TODO：本步把 `.img` 的两类帧都实现了（16 位 A1R5G5B5 与别名帧 `tag 0x11`），
  但**8 位调色板帧**尚未在真实文件上遇到，遇到会直接报错而不是猜。
* **转向 = 镜像**：官方靠动画速率取负（`IRDActiveObject_vmt37C`），等价于**以角色脚点为轴
  水平翻转整块画布** ⇒ 每层左边缘 = `角色屏幕x − (偏移 + 精灵宽) + 1`（未翻转时 = `x + 偏移`）。
  实现见 `game.rs::layer_screen_pos`，逐像素回归测试见 `game.rs::左右朝向互为镜像_站立与行走`。
* 影子：脚下椭圆，随跳跃高度缩小变淡（高度来自弹道，见 §5）。
* HUD：5×7 点阵字体（自绘，无字库依赖），显示动作状态 / 坐标 / 高度 / 帧号。

## 7. 确定性回放（无头模式）

`--headless` 用一条**纯函数式**输入时间线（`crates/dnf-app/src/script.rs`）驱动角色：
**同一步号 ⇒ 同一输入 ⇒ 同一画面**。因此可以：

* 导出关键帧 PNG（动作切换点 / 跳跃最高点 / 起跳 / 落地）供目视验证；
* 打印逐帧轨迹（`--trace`）核对帧序、坐标、高度；
* 在测试里断言帧序单调、「保持帧被放行」、落地帧必须播到等官方语义。

## 8. 明确的已知缺口

- 官方状态请求、优先级仲裁、回执与权限切换的瞬态没有逐指令复刻。
- 房间仍使用既有通行带夹取；49FD80逐像素碰撞、495010沿墙补偿未完整接通。
- 当前只接入鬼剑士普通跳跃；其他职业帧界、受控跳跃和空中攻击未接通。
- 攻击/技能判定、物件动画、换房、音效及其他背景层仍按第一阶段范围处理。

# 音效系统实现与验证

2026-10-11已接入实际声音输出。默认窗口模式读取原版audio.xml及SoundPacks，解码并播放角色语音、短剑挥动、起跳与落地。纯Rust标准库加Windows系统API，无第三方运行时依赖。

当前索引为1501 EFFECT、241 RANDOM、1818资源；现有17个标签去重为28个声音，包含走跑循环、突刺／上挑和哥布林命中。选用素材为PCM WAVE，包含8位／16位单声道44100Hz；MINERALSWD_TOUCH已缓存，尚未挂到移动事件。

| 事件 | 标签及当前触发方式 |
|---|---|
| 普攻语音 | R_SM_ATK，33/33/34，每段开始一次 |
| 空中攻击语音 | R_SM_JUMP_ATK，50/50，空中攻击开始一次 |
| 起跳 | JUMP_START + SM_JUMP，物理飞行阶段开始 |
| 落地 | JUMP_END，接触地面一次 |
| 短剑挥动 | Attack1/2、JumpAttack用R_MINERALSWDA；Attack3用MINERALSWDB |

语音入口来自`src/game/ui/char_server_info.cpp`状态7/8和跳跃状态6；鬼剑士字符串由`sub_5EEE40`配置。武器种类0的A/B标签可在swordman.chr的首个`[weapon wav]`块找到。

**挥剑时间与A/B选择仍是重制同步策略，尚未定案为原版规则。** 武器ANI没有显式发声标签，当前读取武器层首个ATTACK BOX，零基帧为Attack1=3、Attack2=2、Attack3=2、JumpAttack=2。跨越这个帧界时只播放一次，两个武器层共用一次性事件；动作提前结束或落地时取消未触发的挥动音效。原版精确声音门、A/B选择仍需客户端录音/代码交叉取证。

`dnf-data/src/audio.rs`负责XML标签、权重解析、SoundPacks索引、RIFF块和PCM解码。支持8/16/24/32位PCM、单/双声道；检查RIFF边界、未知块及奇数填充、格式/对齐、残缺帧。OGG仅识别容器，未解码；不把所有SoundPacks文件都声称为已支持。

`dnf-app/src/audio.rs`负责缓存、随机选择、重采样、混音与异步设备输出。RANDOM按每层权重独立抽取，零权重不参与，递归有深度界；窗口用时间种子，无头导出固定种子40。每声部保持独立播放游标，单声道复制到左右声道，线性插值重采样到44100Hz。32声部上限，当前自定义淘汰策略为高整数优先级保留，同优先级淘汰较早声部；**该声部上限/淘汰策略不是原版FMOD定案**。

音量是线性百分比：`sub_6611E0`将VOLUME_ADJUST乘100存储，`sub_65D990`最终调用FSOUND_SetVolume(255×(10000+adjust)/10000)，因此重制采用`clamp(1+percent/100,0,1)`，不按dB计算。默认总音量100%，另留6dB混音余量。

收到用户失真反馈后，确认旧导出的普攻110个、空攻314个采样触及16位极值；现在使用5ms立体声联动峰值限幅、0.95峰值上限、80ms平滑释放，避免直接硬截断。含32个过载声部的正弦测试验证没有硬削波平顶，分块与连续渲染完全相同。

设备线程独占WinMM句柄、稳定堆内存WAVEHDR及PCM缓冲；以设备完成事件唤醒并加入MMCSS Audio调度，当前16个10ms块最多预排160ms，再加5ms限幅前瞻及设备本身延迟。解除渲染帧限后的启动复查发现首次回调有121..133ms延迟，因此原12块增加40ms余量，渲染用SwitchToThread协作调度。此设置用于本机稳定播放，尚未复刻原版延迟。失焦不再自动清除声音/设备队列，游戏与已有声音继续运行；手动Engine.set_active接口仍可清理设备，带世代编号防旧请求回流。退出依次reset、unprepare、close，设备失败提示后继续游戏。

Windows API生命周期与事件语义参考[音频缓冲](https://learn.microsoft.com/en-us/windows/win32/multimedia/audio-data-blocks)、[waveOutOpen](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutopen)、[MMCSS线程注册](https://learn.microsoft.com/en-us/windows/win32/api/avrt/nf-avrt-avsetmmthreadcharacteristicsw)。原版捆绑FMOD为32位，64位重制不直接加载它。

```powershell
cd custom-dnf
cargo run --release                         # 默认实际发声
cargo run --release -- --volume 60          # 音量百分比
cargo run --release -- --mute               # 静音，不打开音频设备
cargo run --release -- --audio-selftest     # 实际播放、重叠、手动停止/恢复接口检查
cargo run --release -- --headless --script attack --frames 120 --audio-out out/attack.wav
cd ..
python tools/verify_custom_audio.py
```

音频自检的`focus_stop_resume`日志/报告字段保留历史名称，当前测试显式调用Engine.set_active接口；游戏窗口已经不把该接口与失焦相连，后台音效继续运行。

最终验证产出在`out/audio-verified/verification.json`：实际设备非静音缓冲完成、重叠声部、普攻基础6个声音请求与3次命中的6个附加请求、空攻/起落5个事件；此次设备自检和两种窗口回放的队列耗尽均为0。音轨触顶采样0、重复导出逐字节一致、静音导出全零、静音窗口不打开设备。115项工作区测试及clippy/fmt通过。原生窗口截图同目录，音轨可独立播放。

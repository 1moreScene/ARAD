# 按键管理器与失焦继续运行

当前世界逻辑不再因失焦暂停。移动、奔跑和攻击输入统一走按原版重建的CNCommandChecker；F7显示记录和匹配状态，`--show-keys`启动时打开查看，`--info`打印全部绑定和技能命令模板。

## 失焦行为

窗口失焦或最小化时停止接收键盘/鼠标输入，清理旧按键手势，继续60Hz世界逻辑、动画、跳跃物理、技能冷却、目标恢复/死亡/复活、特效和现有音效。恢复焦点时先取得有效设备快照作为基线，不把后台按住的攻击/跳跃键当成新按下；设备暂时未能Acquire/GetDeviceState时，也继续世界并等待有效输入样本。

保留用户先前要求的焦点钉住策略，F10解除/恢复；解除后可切到别的应用验证后台运行。最小化时不抢回焦点，输入判定同时检查IsIconic、前台窗口与线程焦点。属性/装备面板的显式战斗暂停仍保留，这是独立的调试交互行为。

`crates/dnf-core/src/key_manager.rs`是共用实现，`Actor.commands`保存唯一历史。旧DashRecognizer仅为兼容外壳，委托同一匹配器，不再维护另一套奔跑算法。AxisInput保留旧API兼容，当前角色不再使用其独立方向栈。

方向允许集合为水平{LEFT,RIGHT}和垂直{UP,DOWN}，从最新记录往前取held，因此后按优先、松开回落。同一采样多个键按逻辑ID顺序入队，快捷栏不加入九逻辑命令历史，避免错误打断奔跑键序。

记录默认保留10000ms，只裁去头部已松开且按下时间过期的前缀，遇仍held记录停止。按住不追加记录；release保留按住总时长并在该帧标changed。焦点恢复/重绑定的基线为应用适配策略：保持方向可恢复移动，动作不凭空产生新按下。

## 命令触发和权限

触发模式：DOWN=0、DOWN ONCE=1、UP=2、UP ONCE=3。状态：Idle0、Hit1、Held2、Suppressed3。DownOnce命中后保持/被禁用等待释放，避免长按反复触发；UP模式可保持释放匹配，UP ONCE仅释放边沿。

每段是键组、最小按住时长、后续时间窗。零最小按住的和弦跨度≤100ms，正最小按住使用共同保持区间；从历史末尾逐段回溯，只匹配连续后缀。普通零时长段按按下时间判断间隔，长按段按共同结束时间判断。命令排序沿4BF910采用稳定优先插入，长序列与更严格的可包含条件优先；不把未知不同键组随意按ID排序。

已接通普通攻击、跳跃、左右双击奔跑与基础上挑；长按、续段帧门、空攻次数、MP/冷却等仍由角色状态权限控制。两次左右按下窗口500ms；反向连点的匹配候选与持续奔跑分开。输入管理器每个世界步都更新，包括角色卡肉期间，因此卡肉不会暂停按键时钟，也不会把期间的旧按下缓存到恢复后执行。

## 底层键盘与边界

重制使用系统DirectInput8/c_dfDIKeyboard，读取256字节高位状态，协作模式6（前台、非独占）；`keyboard.rs`持有/释放COM设备，失焦Unacquire，恢复再Acquire。原版是较早32位DirectInput接口，此处为64位适配，实现相同即时DIK状态语义，不是载入原版DLL。原生采样能区分主Enter/NumEnter及修饰键左右侧，失败时等待有效样本；初始化失败才明确回退GetAsyncKeyState。

接口资料：[微软设备数据格式](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee416593(v=vs.85))、[GetDeviceState](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee417897(v=vs.85))。GUID/结构声明交叉核对本机Windows SDK dinput.h，使用SDK dinput8/dxguid导入/静态格式数据，不增加第三方运行时依赖。

已实现键盘路径、核心逻辑通道开关与逻辑注入接口。原版物理鼠标/手柄绑定适配、全部技能执行/取消权限、完整设置UI/账号同步仍未实装；不可把命令模板注册等同于所有技能可施放。

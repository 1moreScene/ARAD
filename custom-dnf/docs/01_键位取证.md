# 官方默认键位 —— 取证报告

> 目标：`custom-dnf` 的键位必须与官方一致，**不允许凭空猜**。
> 本文记录逐字节取证的过程、结论，以及**取证失败的路径**（避免后来者重复踩坑）。

2026-10-11后续已定位439AB0游戏层绑定，结合415240的107槽表，21条默认键位全部确证；原版当前只读采样也确认了九逻辑绑定。旧失败路径保留为历史，不再代表当前证据等级，详情见[10](10_按键管理器与失焦继续运行.md)。

## 三、方向键：逐字节确证

### 3.1 现场

`ARAD.exe` VA `0x415240`（`sub_415240`，引擎键盘设备容器的初始化函数）。反汇编：

```asm
00415240  b8 1d000000        mov  eax, 0x1D
00415245  898120030000       mov  [ecx+0x320], eax        ; 槽 4  = LCTRL
0041524b  898124030000       mov  [ecx+0x324], eax        ; 槽 5  = LCTRL
00415251  b8 2a000000        mov  eax, 0x2A
00415256  89812c030000       mov  [ecx+0x32C], eax        ; 槽 7  = LSHIFT
...
00415273  ba 08000000        mov  edx, 8
00415278  b8 09000000        mov  eax, 9
0041527d  c78110030000cb000000   mov [ecx+0x310], 0xCB     ; 槽 0 = ← DIK_LEFT
00415287  c78114030000cd000000   mov [ecx+0x314], 0xCD     ; 槽 1 = → DIK_RIGHT
00415291  c78118030000c8000000   mov [ecx+0x318], 0xC8     ; 槽 2 = ↑ DIK_UP
0041529b  c7811c030000d0000000   mov [ecx+0x31C], 0xD0     ; 槽 3 = ↓ DIK_DOWN
...
```

### 3.2 这张表怎么用（自证它确实是「键槽 → 扫描码」）

`sub_415200(this, slot)`：

```c
return *(this + 12) != 0
    && (v2 = this + *((uint32_t *)this + slot + 196))[269] != 0   // 当前帧该扫描码是否按下
    && v2[525] == 0;                                             // 上一帧未按下（上升沿）
```

* `*((uint32_t*)this + slot + 196)` = `this[784 + 4·slot]` = **`+0x310 + 4·slot`**，正是上表。
* 取出来的值再当作偏移去读 `+269`（当前帧）与 `+525`（上一帧）两张 256 字节状态数组
  —— 只有 0..255 的**扫描码**才能这么用。

⇒ 该表是 **DIK 扫描码表**，且槽 0..3 就是四个方向键。与 `docs/90_发现日志.md` 会话 12/13
的记载（DIK 203/205/200/208 = VK 37/39/38/40）完全互证。

### 3.3 交叉印证

* `docs/90` 会话 12：「默认方向键已确证 = DIK 203/205/200/208（= VK 37/39/38/40）」
* `src/game/ui_icon_perf.cpp:9210`：选角键盘导航用 `sub_415660(37/38/39/40, ...)`
  —— `sub_415660` 是 `GetAsyncKeyState(vKey)` 包装，VK 37/39/38/40 与上表一一对应。
* 本工程 `dnf-app/src/win32.rs` 的 `vk_to_dik()` 也复现了这条规律：
  方向键是「扩展键」，`MapVirtualKeyW` 给出 `0x4B/0x4D/0x48/0x50`，**补 `0x80` 位**后
  正好等于官方表的 `0xCB/0xCD/0xC8/0xD0`。

## 四、攻击 / 跳跃 / 技能键：取证失败的完整路径

结论：**本机客户端（40jp 单机版）没有把这三个键的默认值以可提取的形式留在任何文件里。**
以下是逐一排除的证据，供后续研究直接跳过：

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 全盘扫 `ARAD.exe` 里 `{C8,D0,CB,CD}` 作为立即数的簇 | 只有 `sub_415240` 一处（就是方向键表）+ 两处误报（跳转表常数、Unicode 区间表）。**没有** 9 元组命令键表 |
| 2 | 扫 `Z/X/C = 0x2C/0x2D/0x2E` 连续 dword | 全文件只有 1 处（文件偏移 `0x338010`，是稀有字符映射表），且引用它的 `0x5DA980` 只是「值 → 值」查表，与键位无关 |
| 3 | 扫 `A S D F G H`（`0x1E..0x23`）连续 dword | 0 处 |
| 4 | 找键位设置窗口用的键名字符串（`Backspace`/`PageUp`/`DIK_`…） | `ARAD.exe` 里**完全没有**；键名来自 PVF 字符串表 |
| 5 | 找 INI 读写 API 的调用点（`ARAD.exe` 确实导入了 `Get/WritePrivateProfileStringA`） | 没有任何代码引用这两个 IAT 项（死导入） |
| 6 | 列 `ARAD.exe` 引用的全部配置文件名 | 只有 `./ARAD.cfg`、`DebugConfig.txt`、`RDARKeyIndex.dat`。`ARAD.cfg` 是**明文**的，里面只有 `[DNF COMMON]` / `[ID guest]` / `LATENCY LEVEL` / `ZOOM EFFECT`，**没有键位** |
| 7 | 客户端目录里的 `DFighter.ini`（348B，2006-06-13 原始 Neople 文件，内含明文自名 `DFighter.ini`） | 数据区被 Neople 自有算法加密；单字节 XOR / 加减 / 循环移位暴力全部失败；**且没有任何二进制引用 `DFighter.ini` 字符串**（`ARAD.exe` / `nengine.dll` / `arad_helper.dll` / `AradServer.exe` 全无）⇒ 本客户端根本不读它 |
| 8 | 私服服务端 `AradServer.exe`（13.6MB）搜 hotkey/QuickSlot/KeySet + 方向键簇 | 全无 ⇒ 默认键位也不在服务端 |
| 9 | 遍历 `ImagePacks2` 找「操作说明」图（`sprite_interface_tutorialtip.NPK`） | 26 张 163×98 的**插画**（职业变更/活动图），不含按键说明；键位说明在 PVF 字符串表里 |
| 10 | `ARAD.exe` 里 `SKILL\0` / `ATTACK\0` / `JUMP\0` / `BUFF\0` 是否成簇 | 全部落在 `SCORE_*`（战绩统计）等无关字符串群里 |
| 11 | `sample/skillsample.skl` 的 `[command key explain]` | 只是 UI 展示文本（`커맨드 : ↓ → ↓`），不含键位值 |

### 4.1 为什么官方客户端会这样

官方 DNF 的键位设置是**账号数据**：客户端从服务器取回配置，用户修改后再回传。
`sub_415240`是引擎层的物理键槽表，439AB0另有游戏层默认绑定，随后可由配置覆写。
旧稿“客户端无需硬编码完整默认表”的推断已被该入口否定，不能将当时没有找到表写成表不存在。

**推论（未证实）**：`DFighter.ini` 很可能就是这份配置的本地缓存（Neople 自有加密），
只是本客户端版本已经不读它了（文件名在任何二进制里都搜不到）。

### 4.2 因此本工程的取舍

* 全部21默认绑定按415240+439AB0实现并标注确证证据；
* Buff使用实测Space，废弃旧B占位；
* 全部键位支持 `data/keymap.txt` 覆盖，且覆盖后自动降级取证等级；
* 用户按官方客户端「键位设置」界面校正后，写进 `data/keymap.txt` 即可。

## 五、复现取证的命令

```powershell
# 1) 反汇编 sub_415240（方向键表）
#    需要 capstone： python -m pip install capstone
python - <<'PY'   # 见 tools/ 侧习惯；Windows 下用 @' ... '@ | python -
import capstone, struct
d = open(r"40jp-client\40jp单机版\ARAD.exe","rb").read()
md = capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_32)
for ins in md.disasm(d[0x15236:0x152A5], 0x401236):
    print(hex(ins.address), ins.mnemonic, ins.op_str)
PY

# 2) 参数：PE 的 .text 段 VA 0x401000 → 文件偏移 0x1000，故 文件偏移 = VA - 0x400000
```

# 3) 取官方命令词表
python tools/pvf_reader.py   # 或用本工程：cargo run --release -p dnf-app -- --info
#    skill/rdarkeyindex.dat 的内容见本文第二节

# 霸体、无敌状态与角色轮廓（2026-10-12）

目标为 `SUPERARMOR`（霸体）和 `Invincible`（无敌）。`SUPERARMO` 是拼写遗漏；`Invisible` 是隐身，不属于本次需求。以下结论针对本地 **40JP / Arad40** 的 ARAD.exe 与 Script.pvf，不扩展为所有 DNF 版本的结论。

## 1. PVF → 当前动画帧 → 受击门

官方动画解析器只识别以下三个 `[DAMAGE TYPE]` 值，写入 88 字节帧结构的 `+52`：

| PVF 值 | 数值 | 本次实现 |
|---|---:|---|
| `NORMAL` | 0 | 正常接受伤害，交给调用方处理受击反应 |
| `SUPERARMOR` | 1 | 接受伤害，抑制普通受击反应；致死仍可死亡 |
| `UNBREAKABLE` | 2 | 无敌帧：排除受击判定，不产生本次命中的伤害和反馈 |

不要在 `.ani` 中自造 `Invincible` / `Invisible` / `SUPERARMO` 标签。本地全包扫描：含 NORMAL 的条目 12774 个、SUPERARMOR 70 个、UNBREAKABLE 25 个；也有 NONE 10 个、LINEARDODGE 2 个，但官方 DAMAGE TYPE 的三分支不识别后两种异常值，本实现按 NORMAL 处理，保留原文供诊断。计数是**包含该标签值的文件条目数**，不是帧数，也不是技能数。

可以复查的原始链路：

1. `src/game/anim_parser.cpp` 的 `.ani` 解析体将 DAMAGE TYPE 写至帧 `+52`。
2. `0x493400` 切换帧，将 `ecx = 动画对象 +60`，调用 `0x493120` 复制当前帧。
3. `0x493120` 将源帧 `+52` 复制至目标 `+52`。因此运行时字段地址为 **动画对象 +60+52 = +112**。
4. `0x4A2C40` / `0x4AED20` 从动画对象 `+112` 取当前伤害类型。对象 `+642` 开启时改取对象 `+644` 的运行时覆盖值。
5. `0x4E5C10`（虚表偏移 `+612 / 0x264`）设置 `+642` 与 `+644`。关闭覆盖后恢复读取当前动画，不应固定恢复成 NORMAL。
6. `0x4A2BB0` 检查受击使能、当前受击盒与伤害类型，**类型 2 不通过**；`0x4D5B30` 的普通反应条件允许类型 0/1。攻击侧另有自己的 ATTACK BOX 与使能门。

这也修正旧转写中将“动画 +112”注释为“帧率态”、将类型 2 注释为“冻结帧”的解释：此处存的是 **DAMAGE TYPE**，不是播放速率。`0x4D5170` 写对象 `+6552` 的独立霸体字节，是另一条状态通道；没有证据说明所有 `.ani` SUPERARMOR 帧必须先写该字节。

## 2. 上挑证明不能只读动画

本地 `character/swordman/animation/attack3.ani` 全部九帧为 NORMAL，上挑仍具有运行时霸体：`0x5F39F0` 的 state8 / skill46 分支，在 **0x5F59BF / 0x5F59C1** 压入两个 1，于 **0x5F59D2** 调虚表 `+0x264`，即设置类型覆盖 `(开启=1, 类型=1)`。

**上挑并非全程霸体**。重新检查 `0x5F10C0` 的 state8 分支：skill46、对象+8220尚未解除、当前动画帧 `+148 > 1` 时，调用虚表 `+612(0,0)` 并将解除标志置1。原始汇编 **0x5F11BD** 比较帧索引与1，**0x5F11D0** 执行解除调用。这是明确的出场帧门：**只保护零基帧0/1，第3帧（索引2）及后续收招无上挑自带霸体**。上一版只查开启调用，漏查了这一 tick 解除分支，将整段 UpperSlash 都设为霸体；现已修正。前两帧原始DELAY各50ms，持续时间受动画速率和逻辑采样影响；不能写死一个独立于攻速的毫秒时长。

本实现区分动画帧状态、动作状态和带来源编号的 Buff。上挑入场赋予动作霸体，到帧索引2时一次性清除，也会在动作退出或 teleport 时清除；独立 Buff 不随上挑帧门清除。技能施放失败不会赋予霸体。动画帧状态每次逻辑推进后从**身体动作的当前帧**同步，时装、武器和技能光效不能改变角色的受击类型。

## 3. 官方红色轮廓的来源

已闭环的直接证据：

| 地址 | 行为 |
|---|---|
| `0x605920` CNSuperArmor 周期入口 | 给宿主设置运行时类型 1；条件允许时开启轮廓 |
| `0x605989` 附近 | 压入 `0xFF0000FF`，虚表 `+284` 调用参数为 `(1, 0xFF0000FF, 1, 2)` |
| `0x42A8D0` 轮廓 setter | 保存 enabled 到对象 +248、颜色到 +252、抖动标志到 +256、距离到 +260 |
| `0x499C70` 绘制主体 | 抖动模式从八个非中心方向选择一个，乘距离；先绘制着色偏移副本，再绘制原角色 |
| `0x499E87` | 使用 `0x96FFFFFF` 调制副本透明度，即 alpha 150 |
| `0x4917A0` | 将源颜色最低/第三字节交换后传给渲染器，证明颜色打包为 ABGR；`FF0000FF` 是红色 |
| `0x6059A0` 移除入口 | 清除类型覆盖，关闭该轮廓 |

这里的视觉轮廓由**精灵透明区域和着色偏移副本**形成，不是矩形框。`SuperArmorEffect.ani` / `SuperArmorBody.ani` 是另外的霸体附属光效，不能将它们直接当成角色红色轮廓。

本地软件渲染使用同样的红色、alpha150 和 2px 距离；所有身体/装备副本先绘制，再绘制全部正常层，避免出现装备内部的红色接缝。黑色像素也会变成红色，因为使用 RGB 替换而非乘色。左右翻转、锚点、相机、跳跃高度、震动偏移沿用已有角色合成逻辑。

**闪烁与随机偏移需区分**：这里没有轮廓透明度周期性开/关的证据，随机偏移不等于霸体应一直闪烁。官方 `0x499C70` 还有 `+256=0` 的固定八方向绘制分支，但 `CNSuperArmor` 附属物明确选择了随机偏移分支；不能将它泛化为上挑等所有技能的显示规范。

**当前本地视觉策略**：每次绘制八方向固定红色副本，轮廓持续显示，颜色/透明度不随逻辑步或渲染帧变化。上一版每步只画一个改变方向的副本，导致视觉断续，现已移除。这保留已验证的红色与2px距离，但不宣称像素级还原了官方所有霸体入口。来源叠加仍采用无敌 > 霸体 > 普通优先级。

## 4. 无敌与描边的验证边界

无敌有两个可确认入口：动画 UNBREAKABLE，以及运行时类型覆盖 2 / 关闭受击使能。`monster/spider/spiderbossani/burrowstart.ani` 含实际 UNBREAKABLE 帧，已纳入自检。精灵 Buff 使用 `InvinsibleFairy` 的历史拼写；`.obj` 选择精灵类型，其生效/到期还需要运行时代码，并非 `.obj` 自带轮廓颜色即可完成。

**尚未确认一条适用于所有 40JP 无敌状态的描边颜色调用链**。当前给无敌绘制白色 2px 轮廓，作为 custom-dnf 的可辨识显示约定。该选择写在 `protection_visual.rs` 和自检报告中，不能将白色描述为已还原的官方规范。无敌仍正常显示角色、播放动作、允许移动；没有实现隐身。

## 5. 实现接口与使用

`dnf-core::protection` 提供 Normal / SuperArmor / Invincible 独立状态层；同来源刷新，不同来源可叠加；限时来源按世界逻辑时钟到期（命中停顿期间也推进，现有属性面板暂停世界时不推进）。移除无敌来源后自动显露仍有效的霸体来源。

```rust
use dnf_core::protection::Protection;

actor.protection.grant(1001, Protection::SuperArmor, Some(5000.0));
actor.protection.grant(1002, Protection::Invincible, Some(1000.0));
actor.protection.remove(1002); // 仍保留1001的霸体
let outcome = actor.receive_damage(20);
```

`receive_damage` 返回 Rejected / Armored / React / Lethal，调用方只有在接受命中后才产生卡肉、命中音效和受击反应。测试哥布林的实际 `hurt_boxes` / `hit` 链已经使用相同状态层，无敌在 HP、命中次数、特效与停顿之前拒绝。**当前测试哥布林仍无正式攻击 AI；玩家普通受击动画、强制抓取破霸体、全部 Buff 技能及服务器事件尚未接通**，玩家接口已可供这些调用方使用，本次不声称完成所有动作/战斗状态。

窗口测试键：**F8 切换测试霸体，F9 切换测试无敌，再按解除；F5 清除测试来源**。上挑自带动作霸体，不依赖 F8。`--trace` 末尾显示 `protection=`。

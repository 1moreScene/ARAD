## 2. 输入记录与命令识别

`CNCommandChecker` 主虚表 `0x6C490C` 的实际槽：

| 槽 | 函数 | 作用 |
|---|---|---|
| +004 | 4BF380 | 每帧更新记录，再按命令优先级调用匹配器 |
| +028 | 4BF3D0 | 从尾向前查询允许集合中最后一个held记录 |
| +02C | 4BF450 | 查询某逻辑命令最后记录的held/changed |
| +030 | 4BF250 | 查询绑定的设备按键状态 |
| +03C | 4BF4C0 | 查询释放/释放边沿 |
| +048 | 4BFBC0 | 查询命令结构+36是否为匹配态1，同时检查+40使能 |
| +050 | 4C0090 | 注册命令序列并调整记录保留时限 |
| +070 | 4C0140 | 更新16字节输入记录 |
| +074 | 4BF540 | 匹配24字节命令段序列 |

输入记录是 `{id:u32, press_ms:u32, hold_ms:u32, held:u8, changed:u8, padding}`。
逻辑id按RDARKeyIndex：上0、下1、左2、右3、技能4、攻击5、跳跃6、宠物7、Buff8。
新按下追加记录，保持时更新hold_ms，释放时held清0并标记changed；没有“整个轴必须中立”的条件。
两轴允许集合分别为{2,3}和{0,1}。从尾向前查询有效记录，所以后按优先，松开后回落。
同一设备采样内多个键同时按下按逻辑id顺序进入历史；方向解析与命令识别共用这一历史。

4B5B80的奔跑注册字节：`4B5DC6 mov [ebp-1C],0x1F4`，随后两次调用4B5910加入相同段。
每段只有一个逻辑方向id，最小按住时长0，窗口500ms，模式1要求新按下边沿。
因此是连续的逻辑命令后缀“右右”或“左左”，按下到按下不超过500ms；插入上、下、攻击等记录会打断后缀。
保持一个键不会追加新按下记录，不会自动跑；长按第一下再迅速松开重按，若两次按下相隔超过500ms也不匹配。
实现见 `../crates/dnf-core/src/dash.rs`。时钟用整数毫秒比较，避免60Hz浮点步长使500ms边界变成500.00004ms。

命令结构+32是模式，+36是状态(0未匹配、1命中、2保持、3已消费/失能后的等待释放)，+40是使能。
`4AFEC0` 按角色动作状态更新全局使能：自由态开放两条奔跑命令；状态11等会关闭它们，跳跃则有自己的权限分支。
不能把命令命中直接永久保存成“正在跑”。

## 3. 速度、位置与朝向

| 档位 | x直向 | x斜向 | y直向 | y斜向 |
|---|---:|---:|---:|---:|
| 地面步行 | 143 | 119 | 114 | 95 |
| 地面奔跑 | 286 | 238 | 136 | 114 |
| 普通跳跃，步行起跳 | 143 | 119 | 57 | 47 |
| 普通跳跃，奔跑起跳 | 286 | 238 | 68 | 57 |
| 受控/技能跳跃分支 | 286 | 286 | 0 | 0 |

任一轴方向槽为4则选直向参数，否则选斜向参数。每轴速度：

```text
v = axis_parameter * direction_sign * runtime_move_speed / 1000
direction 0/2 → -1；1/3 → +1；4 → 0
```

不做cos45°归一化。鬼剑士PVF基础move speed=850；实测账号运行时为842，不能拿裸基础属性直接当装备后的角色属性。
普通跳跃y先整数除2再乘移速，95/2=47，不能使用47.5。

关键区分：`vt+1132 → 4B04B0` 从输入记录取原始方向；`vt+184/188 → 4996F0/499730` 从物理速度分类：
`v > 5`为正向，`v < -5`为负向，闭区间[-5,5]为无动作方向4。
状态机用后者决定站/走、改向、奔跑取消。很小的非零速度可以改变浮点位置，但动作方向仍为4。

真正的角色控制器积分器是49FD80，由4A0790传入本帧dt毫秒：

```text
v1 = v0 + acceleration * dt_ms / 1000
position1 = position0 + (v0 + v1) / 2 * dt_ms / 1000
```

加速度0时是匀速积分；恒定重力下是精确抛物线积分，不能用旧稿的粒子积分器推断角色时钟。
控制器+4/+8/+12为f32位置，+16/+20/+24为f32速度，+28/+32/+36为i32加速度。
4A0650经432F40取整数坐标：正数加0.5、负数减0.5后截断，即四舍五入且半值远离0。
49FD80还逐像素调用地面/平面碰撞查询，碰撞返回4。本重制目前保留既有房间通行带夹取；未完整复刻官方逐像素障碍查询和495010沿墙补偿。

朝向读取`vt+152 → 498F60`为控制器+52；`vt+144/148 → 498F00/498F40`分别为带本地权限检查/直接设置的接口。
普通自由移动只在水平动作方向有效时改朝向，纯纵深保持原朝向。

## 4. 奔跑状态机与本次问题

官方有效动作状态为this[1639]，奔跑为11，自由态为0。走/站是自由态内部动作，不是两个独立官方状态。
进入11时4B89D0写跑速参数，切dash motion，并把移动/动画属性类别都设成1。
4B7430 case11：

```text
若 vx动作方向 == 4：只有 vy动作方向 != 4 才继续奔跑
否则：只有 vx动作方向 == facing 才继续奔跑
不满足 → vt+560请求自由态0
```

因此反向退出，松开反向键也不会凭空恢复此前的跑步开关。
只有纯纵深输入时可以维持已进入的奔跑，但双击↑↓本身不能启动奔跑。

这里还有必须保留的层次：`vt+560 → 4E7A80`写待处理状态+616及优先级+636；它不直接写this[1639]。
4E8130把状态请求发到UDP type5同步链。方向与状态的应用有时序，候选、待处理请求、有效状态可以同时不同。

用户操作的只读采样 `../../work/official_movement_live.jsonl` 和补充采样 `../../work/official_movement_mash_walk.jsonl` 显示：

- 按右后再按左会后按优先转向，释放左会回到右。
- 右双击进入11，按反向后回0。
- 右保持时连续左记录仍会使左左命令+36为1/3；补充采样还捕获了pending_state=11而有效state=0。
- 可短暂采到11后立即回0，不能把“视觉上未持续跑”写成“输入层从未匹配/官方内部从未出现11”。

`custom-dnf` 现在把`dash_candidate`与有效奔跑分开；同时持有左右键时不建立持续奔跑，并在反向时取消已有奔跑。
**左右重叠时的抑制属于实测结果的本地状态归并，不是4BF540中的分支。**完整请求、网络回执、权限重算的逐帧瞬态尚未逐指令复刻。
旧实现的错误核心是把命中结果写成跨方向永久保持的dash_armed；旧文档再错误地把轴中立和“反向仍跑”当成已确证。

## 5. 普通跳跃的三个子状态

本篇实现鬼剑士普通跳跃。角色构造链579A60 → 5EEE40写入三个帧下标：
this[1716]=1、this[1717]=8、this[1718]=15。它们不是自动搜索到的保持帧7/14。

| 子状态 | 地面平面移动 | 动画与转换 |
|---|---|---|
| 6/0准备 | x/y参数都为0，保持朝向 | 从帧0开始，100%速率；达到帧1后发送6/1并读取jump power |
| 6/1飞行 | x继承起跳档位，y暂存参数整数/2；普通分支可调整方向和落点 | 发射后设帧1；vz<=0且当前帧<8则直接设8；下落并碰地时请求6/2 |
| 6/2落地 | x/y参数都为0，保持朝向 | 设帧15，100%；末帧50ms播完后请求状态0 |

奔跑起跳时，4B89D0在6/0把暂存参数覆盖成286/238/136/114，随后6/1再恢复x及半速y。
落地回自由态，不能靠旧的跑步开关自动恢复奔跑。
起跳准备与落地锁定由动画门控制，不需要拍脑袋的3帧冷却计数。

竖直初速来自495430的整数实参：

```text
power = int(attribute[928] * modifier[942])     // 58E710
speed = int(attribute[956] * modifier[970])    // 495580
weight = int(attribute[984] * modifier[998])   // 4B0D20
denom = (integer_divide(100*weight, speed)-10000)*0.0121 + 2100
vz0 = 4000*power / denom
```

普通重力模式2：无装备修正时a=-1500*speed/100，整数加权。
基础鬼剑士430/68000/95给出v0≈604.5495px/s，g=1425px/s²；理想顶点128.24px、纯飞行约848.49ms。
另加准备100ms与落地50ms才是完整跳跃动作时间；官方账号的装备属性不同，实测高度也会不同。
本工程z绘制偏移用负数表示离地，符号约定与官方控制器正z向上互换。

包的受控标志+6988!=0是另一分支：x286/286、y0、固定重力模式1，朝向受限；不能用它解释普通跳跃。
该技能分支、空中攻击后的权限变化、其他职业专属帧界与动画没有接入当前仅鬼剑士普通操作的重制界面。

## 6. 动画速率

495310将移动属性类别与动画属性类别分别查询。类别0使用传入1000；类别1查询运行时move speed。
495A10再将动画千分值乘0.1写给动画播放器。

| 动作 | vt+888类别(移动,动画) | 动画速率 |
|---|---|---|
| 站立 | (1,0) | 100% |
| 步行 | (1,1) | move speed / 10 % |
| 奔跑 | (1,1) | move speed / 10 % |
| 普通跳跃准备/飞行 | (1,0) | 100% |
| 普通跳跃落地 | (0,0) | 100% |

基础850角色走/跑为85%，不是100%。实测842角色走/跑为84.2%。
10000ms的帧只作为长等待段；普通跳跃的物理门直接跳到其后的8/15，不能通过保持帧位置反推职业帧界。

## 二、资源文件体系（一张图看懂）

```
游戏目录/
├── ImagePacks2/*.NPK          ← 所有图片精灵
│     └── 每个 .NPK 内含多个 .img 文件
│           └── 每个 .img 内含多帧 16bpp 精灵图
├── SoundPacks/*.npk           ← 音效；本轮角色/短剑资源确认RIFF/WAVE
├── Script.pvf                 ← 所有游戏数据（物品/技能/怪物/任务定义）
└── （可执行文件）
```

### 读取链

```
 .NPK 文件
   ↓ npk_reader.py（明文目录：偏移+大小+文件名）
 .img 文件（如 "sprite/character/common/skillicon.img"）
   ↓ img_reader.py（36B 头 + zlib → A1R5G5B5 像素）
 精灵帧（28×28 或任意尺寸的 16 位色图像）

 Script.pvf
   ↓ pvf_reader.py（CRC 变体解密目录 + 内容解密）
 文件列表（48,326 个虚拟文件）
   ↓ read("character/swordman/skill.skr")
 脚本内容（.ani=动画标签 / .equ=装备定义 / .str=文字 / .skr=技能数据）
```

## 三、IMG 精灵格式（渲染的核心）

### 二进制布局

```
[32 字节魔法区]
  +0x00: "Neople Image File\0"     （18 字符 + NUL + 5 字节填充）
  +0x18: DWORD 版本 = 1
  +0x1C: DWORD 帧数

[帧 × N] 每帧 =
  36 字节头：
    +0x00 DWORD 组 ID（同组 = 同一动画的帧）
    +0x04 DWORD 像素格式（6 = A1R5G5B5）
    +0x08 DWORD 宽度
    +0x0C DWORD 高度
    +0x10 DWORD 解压后大小（=宽×高×2）
    +0x14 DWORD 未知1（观测为 0）
    +0x18 DWORD 未知2（观测为 0）
    +0x1C DWORD 宽度副本
    +0x20 DWORD 高度副本
  zlib 压缩的像素数据（解压后 = 宽×高×2 字节）
```

### 像素格式：A1R5G5B5（16 位）

```
位 15    = Alpha（0=完全透明，1=完全不透明）
位 14-10 = Red（5 位，0-31，乘 8 得 0-255）
位 9-5   = Green
位 4-0   = Blue
```

常见值：
- `0x7FFF` = 透明白（A=0，RGB 全 1）——精灵图的空白边缘
- `0x0000` = 透明黑
- `0x8888` = 深蓝灰（不透明）——技能图标底色

**为什么只有 1 位 Alpha？** 2006 年 DNF 的精灵没有半透明像素——
半透明效果（火光/光环/幽灵）是渲染时用 D3D ALPHA BLENDFLAG 做的全图层混合，
不是像素自带的。这大大减小了文件体积。

### 用 img_reader.py 导出

```bash
# 列出全部帧
python tools/img_reader.py sprite_character_common.NPK提取的.img

# 导出为 PNG（可直接用画图/PS 打开）
python tools/img_reader.py xxx.img --png output_dir/
```

### 在你的游戏引擎里用

1. 读 NPK → 按名字找 .img → 解析帧列表
2. 每帧解压 zlib → A1R5G5B5 → 转成你的引擎的纹理格式
3. 同组 ID 的帧按序播放 = 动画
4. 透明像素（A=0）不渲染，其余正常画

## 四、PVF 数据格式（游戏逻辑的核心）

### 目录层

```python
from pvf_reader import PvfReader
r = PvfReader("Script.pvf")
# r.entries = [(索引, 偏移, 大小, 密钥, 路径), ...]
content = r.read("character/swordman/skill.skr")  # 返回解密后的字节
```

### 内容格式（按扩展名）

| 扩展名 | 格式 | 编码 |
|---|---|---|
| .ani | 文本标签（[LOOP]/[FRAME000]/[IMAGE]/[DELAY]/[DAMAGE TYPE]…） | ASCII |
| .equ | 文本标签（[name]/[grade]/[usable job]/[minimum level]…） | EUC-KR/CP949 |
| .str | 纯文本（UI 字符串表，`//` 注释） | EUC-KR/CP949 |
| .atk | 文本标签（attackinfo：[damage]/[attack type]/[push aside]…） | ASCII |
| .skl | 技能定义（[purchase cost]/[type]/[maximum level]/[required level]） | ASCII |
| .map | 地图布局（[player number]/[tile]/[pvp start area]） | ASCII |
| .dgn | 副本定义（[entering title]/[worldmap info]/[minimum required level]） | EUC-KR |
| .chr | 角色定义（[job]/[growtype name]/[initial value]/[HP MAX]） | ASCII |
| .mob | 怪物定义（[ability category]/[HP MAX]/[EQUIPMENT_PHYSICAL_ATTACK]） | ASCII |
| .qst | 任务定义 | EUC-KR |
| .stk | 消耗品定义 | EUC-KR |
| .obj | 物件定义 | ASCII |
| .til | 瓦片定义 | ASCII |
| .img 路径引用 | 在 .ani 的 [IMAGE] 标签里：`` `Monster\Ghoul\xxx.img` `` | ASCII |

**重大发现（会话 7 实证）**：PVF 内 **全部 25 种扩展名的文件都是明文标签文本**
（解密后）——不是后来版本的二进制 token 树。整个游戏的数据就是一堆带 [标签] 的
纯文本文件，用任何文本编辑器都能直接读！

### 动画标签速查（.ani 文件）

| 标签 | 含义 |
|---|---|
| [LOOP] 0/1 | 是否循环播放 |
| [SHADOW] 0/1 | 是否画影子 |
| [FRAME MAX] N | 总帧数 |
| [FRAME000] | 帧开始标记 |
| [IMAGE] `path.img` index | 引用哪个 IMG 文件的哪张图 |
| [IMAGE POS] x y | 帧内贴图偏移 |
| [IMAGE RATE] sx sy | 缩放 |
| [IMAGE ROTATE] angle | 旋转 |
| [RGBA] r g b a | 染色（代码实证：第 4 值为 Alpha，内部字节序 R G B A） |
| [DELAY] ms | 该帧持续毫秒 |
| [DAMAGE TYPE] 0/1/2 | 0=普通 1=霸体 2=不可打断 |
| [ATTACK BOX] x y z w h d | 攻击判定盒 |
| [DAMAGE BOX] x y z w h d | 受击判定盒 |
| [GRAPHIC EFFECT] type | 渲染混合模式（DODGE/LINEARDODGE/DARK/MONOCHROME） |

## 五、角色/怪物渲染原理（DNF 的"纸片人"系统）

DNF 的角色和怪物是 **分层纸片人**（类似皮影戏）：

1. 每个"外观件"（头发/脸/上身/下身/武器/披风）是一个独立的 .img 文件
2. 每个件有多帧动画（站/走/攻/被击/死）
3. .equ 文件定义哪些件组合在一起（穿什么装备显示什么外观）
4. 渲染时按 z 序叠加：最底层身体 → 中间装备 → 最上层武器

对应代码：IRDActiveObject 内嵌 4 个 1364B 子对象 = 4 个"外观件槽位"（武器/披风/…），
每个子对象有独立的动画时钟（可以独立冻结/变速）。

## 六、快速开始：用真实资源画一个角色

```python
import sys
sys.path.insert(0, "tools")
from npk_reader import NpkReader
from img_reader import ImgReader

# 1. 打开 NPK
npk = NpkReader(r"G:\game\DNF2008_ACT1\Client\ImagePacks2\sprite_character_common.NPK")

# 2. 找到鬼剑士站姿
for off, size, name in npk.entries:
    if "swordman" in name and "stand" in name.lower():
        print("找到:", name)
        img_data = npk.read(name)
        break

# 3. 写出 .img 文件并解析
open("temp.img", "wb").write(img_data)
img = ImgReader("temp.img")

# 4. 导出第一帧为 PNG
png = img.get_png(0)
open("swordman_stand.png", "wb").write(png)
print("导出成功！用画图打开 swordman_stand.png 看看")
```

## 七、还没搞定的（如果你想做完整克隆）

| 事项 | 重要度 | 说明 |
|---|---|---|
| IMG 调色板模式 | ★★★ | format ≠ 6 的 IMG 可能用 8bpp 调色板（未遇到样本） |
| .skr 技能文件格式 | ★★★ | 可能是文本（待用 pvf_reader 解一个看） |
| 地图/副本格式 | ★★☆ | `.map`/`.til` 标签已解析；**房间宽 = 瓦片条数×224**、瓦片条 224×480、**内部分辨率 640×480**、**绘制=按世界 y 的画家序**；`[pass type]` = 14×30×16px 官方地形网格（0=可通行/2=阻挡，含斜坡），`[far/middle/near sight scroll]` = 官方视差滚动率，图层叠加须 alpha 混合（会话 11–13 破解，实现见 custom-dnf） |
| 声音资源位置 | ★☆☆ | SoundPacks/*.npk 内；依audio.xml路径和文件头识别，不按扩展名或旧OGG结论猜格式 |
| 服务器协议 | ★★☆ | docs/24 已有 91 种客户端发包 + 40+ 收包 case（够参考） |
| 字体渲染 | ★☆☆ | NeopleFontFile（自研字体格式，低优先级） |

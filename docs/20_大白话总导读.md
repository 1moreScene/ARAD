## 1. 这个工程在干嘛（三句话）

1. 2006 年 6 月 13 日，韩国 Neople 公司编译了一个游戏客户端：**DNF 地下城与勇士的日服版本**（文件名 ARAD.exe，3.9MB）。原始源码从未公开。
2. 我们用逆向工程工具（IDA）把这个程序里的 **12,172 个函数**全部"翻译"回了人能看懂的代码，并且给每一个都标注了它负责什么。
3. 整个翻译过程**每个函数都可以对回原程序验证**（每个函数都带它在 exe 里的"门牌号"，叫 VA 地址），不是猜测，是有据可查的。

**一句话总结：这是一份"游戏客户端的说明书"，精确到每一个函数。**

## 2. 这个游戏客户端是怎么工作的（5 分钟看懂架构）

### 2.1 游戏就是个大循环

游戏程序每秒钟做几十次同样的事：

```
开机 → WinMain (0x401B20)
  → 初始化（D3D8 画面 / DirectSound 声音 / DirectInput 键盘手柄 / 网络 Socket）
  → 主循环（每一帧）：
      ① 读键盘鼠标   → 0x433690 主帧循环
      ② 推进游戏时间 → 16 条"时间通道"（0x4052D0，每条可以调快调慢可以暂停）
      ③ 更新所有对象 → 场景里的角色/怪物/特效各走一步
      ④ 画画面       → D3D8 画到屏幕上
      ⑤ 收发网络包   → 和服务器交换数据
```

**为什么有些函数有"0x401B20"这样的编号？** 那是它在 exe 文件里的地址（叫 VA，虚拟地址）。
就像门牌号——有了它，你随时可以在 IDA 里跳过去看原始机器码，一比一验证我们的源码。

### 2.2 画面上的一切都是"对象"

- 角色、怪物、掉落的金币、技能特效……每个都是一个大结构体（C++ 叫"类实例"）
- 它们的"动作"（被打、攻击、消失）不是直接调用，而是查一张**分发表**（术语叫"虚表"，每个对象出生时背上背一张）
- 这就是为什么源码里大量出现 `vt+200`、`vmt200` 这样的写法——"查分发表第 0x200 号位置"
- 全部 743 个类的分发表都挖出来了：`include/arad/` 目录，每个类一个文件

### 2.3 服务器说了算，客户端负责"演"

2006 年的 DNF 是这样防作弊的：
- **你打没打中怪、打掉多少血——服务器算好了发"命中包"告诉你**（包类型 0x13/0x14）
- 客户端收到包后负责**演出来**：怪物掉血（0x4D4D40）、飘伤害数字（0x4D7960）、
  卡肉顿帧（0x4E5DC0 表现壳）、镜头震动（0x424AB0）、音效（STUCK_BLADE/BLUNT）
- 客户端自己也有一套"本地预演算"（你挥刀的瞬间就出特效，不等服务器往返），
  但真正的扣血以服务器为准

### 2.4 打击感（这游戏最著名的系统）是怎么做的

DNF 打击感的核心叫 **hit stop（卡肉/顿帧）**，原理大白话版：

```
你砍中怪 → 客户端让"攻击者"和"受害者"的游戏时间同时暂停一小会儿
        → 暂停 = 把这个对象的"闹钟"（PauseClock 结构体）按住冻结
        → 时间不走 = 动画停在当前帧 = 你看到的"顿一下"
        → 暂停时长 = 武器/技能自带的数据（每个攻击都不一样）
```

实现代码：冻结 = 0x699030，解冻 = 0x698FE0，全部时间系统在 `src/nengine/time_system.cpp`（这是全工程精修度最高的文件，从它开始读最容易懂）。

叠加在上面的演出：镜头震动（0x424xxx 家族）、暴击特效 1.5 倍（0x4E85E0）、
音效（50 个声道 FMOD）、粒子（.ptl 文件）——全部定案见 `docs/10`~`docs/15`。

### 2.5 防作弊与反逆向（这个客户端的"自我保护"）

- 数值防篡改：血量攻击力等关键数字在内存里加密存储（XOR 交叉校验，读的时候自动解密验算）
- 反调试：启动时检查有没有挂调试器（IsDebuggerPresent），还有代码区 CRC 自检
- 但 2006 年**没有加壳、没有整体加密**——所以我们能直接读
- 详见 `src/game/anim_parser.cpp` 头部注释（0x48B 区）和 `docs/90` 发现日志

## 3. 源码的"三档精度"（诚实说明，看懂这个就不会被数据吓到）

| 档 | 什么意思 | 函数数 | 打个比方 |
|---|---|---|---|
| **T1 精修** | 有完整的结构体定义、每个字段有名字、每行有解释 | 130 | 带家具家电的精装房 |
| **T2 标注** | 每个函数有"这段代码干嘛"的注释 + 它用了哪些资源的证据 | 10,829 | 毛坯房+每间房挂了说明书 |
| **T3 转写** | 只有翻译过来的代码（微软运行库，计划内不精修） | 1,334 | 图纸（能用但没装修）|

**重要**：不管哪一档，**函数体都是 100% 完整的**——没有半个函数缺失。
区别只是"注释的详细程度"。所有函数体都是反编译工具输出的忠实结果，
我们做了**双重审计**证明没有改坏任何一行逻辑（见 docs/18 §终验）。

## 5. 想找某个东西？三种方法（从快到慢）

### 方法一：按名字搜（最快）

```bash
# 在源码里搜任何关键词
grep -rn "Goblin" src/                  # 搜哥布林相关
grep -rn "STUCK_BLADE" src/             # 搜卡肉音效
grep -rn "FlameThrower" src/            # 搜火焰喷射器
```

### 方法二：按地址搜（最准）

```bash
# 在 docs/21 速查手册里查到功能对应的地址，然后：
grep -rn "0x4D71B0" src/                # 定位到命中主处理器的源码位置
```

### 方法三：查速查手册（最系统）

打开 `docs/21_系统速查手册.md` → 找到功能分类 → 拿到地址和文件 → 回源码看。

### 回二进制验证（终极手段）

拿到 VA（如 0x4D71B0）后，在 IDA 里按 G 输入地址，就能看到原始汇编——
和源码逐行对照，验证我们的翻译没错。

## 6. 名词表（大白话解释）

| 术语 | 大白话 |
|---|---|
| **VA** | Virtual Address，函数在 exe 里的"门牌号"（如 0x4D71B0）。全工程唯一 |
| **虚表 / vmt / vt+200** | 对象的"分发表"。对象靠查这张表决定"被打时执行哪段代码"。200 是表内偏移 |
| **RTTI** | 编译器埋在程序里的"类名标签"。我们靠它恢复了 743 个类的名字 |
| **Hex-Rays** | IDA 的反编译插件，把机器码翻译成类似 C 的代码。T2/T3 的函数体都是它的输出 |
| **dump** | 批量反编译的原始输出文本（在 work/dump_*.txt），是 src/ 的上游原料 |
| **L1 / L2** | 精修深度两层：L1=人工逐行精修（130 函数），L2=批量转写（其余） |
| **T1/T2/T3** | 同上的另一套统计口径（见 §3） |
| **CRT** | C 运行库（微软写的 printf/malloc 等），不是游戏代码，计划内不精修 |
| **FMOD** | 2006 年流行的声音引擎，游戏用它播 50 个声道 |
| **NPK / IMG** | 游戏的资源包格式（NPK 是大包，IMG 是里面的图片包） |
| **pvf / .equ / .ani / .ptl / .str** | 游戏的脚本/装备/动画/粒子/声音配置文件格式（全部已解出结构） |
| **hit stop / 卡肉** | 命中时双方时间暂停几毫秒的打击感技术（本游戏的核心手感来源） |
| **子代理** | 主 AI 派出去并行干活的分身（本工程用了 12 个，各自的报告在 docs/90） |

## 7. 常见问题 FAQ

**Q：这份源码能编译出一个能跑的游戏吗？**
A：不能，也不打算能。缺资源文件（.npk 包）、服务器、还有几千个全局状态要拼。
它的价值是**完整可读的逻辑参考**——做研究、写插件、做私服开发参考、学习 2006 年 MMO 架构。

**Q：函数体为什么长这样？变量名是 v1/v2/v3？**
A：反编译工具的输出就长这样（机器码没有变量名概念）。T2 层的注释会告诉你每段在干什么；
核心函数（T1）已重命名成有意义的样子。

**Q：怎么确认源码是对的？**
A：三重验证：① 每个函数有 VA，可在 IDA 对照原始汇编；② 精修前后全量 diff 证明逻辑零改动；
③ 两份独立审计报告（data/audit_*.txt）交叉确认覆盖率。

**Q：我想深入某个系统，从哪篇文档开始？**
A：战斗→docs/10/14；镜头→docs/12；主循环→docs/13；装备→docs/15；怪物→src/game/creature/ 头注释。

**Q：work/ 目录 512MB 能删吗？**
A：能。里面的 IDA 数据库（.i64）和 dump 文本都是中间产物，可从 tools/run_all.py --full 重建。
交付包 zip 里已经排除了它。

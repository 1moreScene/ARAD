# 【40JP逆向源代码工程】子代理重构规范（转写任务统一标准）

> 本文件是本工程所有"反编译→源码"转写子代理的**唯一作业标准**。子代理开始前必须完整读完。
> 铁律：边做边写文档；一切结论标注来源；不做无证据的发明。

## 一、任务本质

把 IDA Hex-Rays 反编译输出（`work/dump_*.txt`）逐函数转写为**语义忠实的可读 C++ 源码**，
放入 `src/` 对应目录。目标不是"能编译"，而是"**人读源码 = 读懂原始二进制逻辑**"。

## 二、硬性格式规范（验收脚本会逐条检查）

1. **每个函数必须有 VA 标记**（验收按此行计数）：
   ```cpp
   // ------------------------------------------------------------
   // 0x57A980 —— 函数名/语义一句话
   // ------------------------------------------------------------
   ```
   （或单行形式 `// 0x4D71B0 sub_xxx`，但必须含 `0x` + 8 位地址）
2. **文件头**：注明来源（dump 文件 + 区块）、置信度、本文件还原函数数。
3. **命名规范**：
   - RTTI 已命名的函数用原名（如 `IRDActiveObject__vmt200`）
   - 未命名的用 `sub_XXXXXX` 原名（**绝不臆造名字**）
   - 语义已确定的可加后缀说明：`sub_4D71B0 /* hit_main_handler */` —— 保持原名+注释
4. **变量命名**：允许把 `v3/v4` 改为有语义的名字（`animObj`/`hpBefore` 等），
   但**不得改变控制流/条件/常数**。所有 magic number 保留原值（`1000`、`0x3E8`、`0.0099999998`）
   并在行尾注释换算（如 `/* 0.01 */`）。
5. **结构体字段**：偏移写进注释 `// +0x200 主状态`；用 `*(int*)((char*)this + 0x200)` 形式
   或已定义的 struct 字段访问均可，但偏移必须可查。
6. **未还原的被调函数**：`extern` 声明 + 原名 + 尾注释冒号语义，如
   `extern int sub_481230(void*);   // 0x481230 特效池申请`
7. **不确定的地方显式标注**：【推断】/【待验证】行内注释，不许含糊过去。
8. **截断函数**：dump 中超 MAXLINES（100 行）被截断的，在源码里写
   `// [截断] 完整输出见 work/dump_*.txt @地址`，并还原可见部分。

## 三、质量纪律

- **一个函数一个函数来**：读完反编译再写，不跳步。
- **常数不许改**：0.0099999998 就是 0.01f 的浮点表示，注释换算但代码里可写 0.01f；
  整数常数（1000ms、0x3E8、5000）**必须原值**。
- **控制流忠实**：if/else/switch/循环边界/短路顺序都必须与反编译一致。
- **vtable 调用保留槽偏移**：`(*(int(__thiscall**)(void*))(*(int*)this + 0x200))(this)`
  写成 `VT_CALL(this, 0x200)` 宏或直接展开均可，但**偏移必须原样**。
- **不合并、不省略函数**：即使 `return 0;` 的空桩也要还原（可群组为一行注释+函数）。

## 五、验收标准（主代理清点）

1. `grep -c "^// 0x[0-9A-F]\{6\}" src/子目录/*.cpp` 之和 = 子代理报告数
2. 抽查 5 个函数：与 dump 原文逐行比对（控制流/常数/偏移）
3. 无臆造函数名（非 RTTI 名必须是 sub_XXXXXX 原样）
4. 每文件头有来源注明

## 六、允许的简化（本阶段）

- 画幅压力：极端复杂的巨函数（>500 行反编译）可先还原前 200 行主干 + `// [待续]` 标记
  （但必须在文件头计数里如实报告"部分还原"数）
- 内联汇编/编译器桩可一行注释带过
- CRT 调用直接用标准库名（memcpy/strcmp/malloc → free 等）

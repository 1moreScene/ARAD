# 10 · 模块：引擎时间系统（16 域积分器 + 可暂停时钟）

> 模块范围：0x4051A0 / 0x4052D0 / 0x698F90-0x699070 + .data 0x79D080-0x79D144
> 源码：`src/nengine/time_system.h` + `time_system.cpp`
> 方法：Hex-Rays 反编译（work/decomp_time.txt）+ 42 轮研究（文档 20 §4）交叉验证
> 更新：2026-10-06（P4 试点，全部【已证实】）

## 1. 系统定位

全库一切"游戏内时间"的源头。两层结构：

```
真实时间 timeGetTime()
   └─ 16 个积分域（tick[i] += rate[i]% × 帧间隔；域0=主时钟, 域1/2=镜头震动, 其余闲置）
        └─ 每对象可暂停时钟 PauseClock（freeze ⇒ now 恒定 ⇒ dt=0 ⇒ 一切更新停摆）
             └─ 语义层（stuck 硬直 / 异常状态 / 演出定格，见 42 轮研究文档 20 §2-§6）
```

hit stop（打击感顿帧）= 冻结受击者/攻击者的 PauseClock —— 本模块即其实现基座。

## 2. 全局数据布局（反编译直证，比研究文档更精确）

| 地址 | 类型 | 语义 |
|---|---|---|
| 0x79D080 | float[16] | 每域小数累积器（增量的小数余量，防精度丢失） |
| 0x79D0C0 | int[16] | 每域速率（百分比，100=恒速） |
| 0x79D100 | int[16] | 每域累计 tick（游戏内"当前时刻"唯一来源） |
| 0x79D140 | DWORD | 上帧 timeGetTime()（步进基准） |

> 研究文档 20 §4.4 曾记"0x79D080 累积器/C0 速率/100 tick/140 锚"（第 17 轮）——本模块反编译完全证实，
> 并补充：累积器是 **float**（非 int），积分用 **double** 中间精度。

## 3. PauseClock 结构（28 字节，字段级定案）

| 偏移 | 字段 | 语义 |
|---|---|---|
| +0x00..07 | — | 反编译未见访问【待验证】 |
| +0x08 | domainId | 时间域 id（0-15） |
| +0x0C | enabled | 已初始化 |
| +0x0D | running | 正在计时 |
| +0x0E | frozen | 冻结中 |
| +0x10 | offset | 未冻结时 now = offset + tick[domainId] |
| +0x14 | frozenValue | 冻结期间返回的定格时刻 |
| +0x18 | duration | 最近一次倒计时的时长 |

与研究文档 20 §4.1 的"28 字节结构：+8 时钟源 id / +12/+13/+14 三标志 / +16 偏移 / +20 定格值 / +24 时长"完全一致。

## 4. 函数清单（5 + 2 个）

| VA | 语义 | 源码函数 |
|---|---|---|
| 0x4051A0 | 16 域初始化（零点/清零/速率=100） | tick_domains_init |
| 0x4052D0 | 逐帧积分（公式见源码注释） | tick_domains_step |
| 0x698F90 | 设倒计时（时长, 起点时刻） | clock_set_countdown |
| 0x698FE0 | 解冻（从定格值续走） | clock_unfreeze |
| 0x699000 | 取当前时刻（冻结⇒恒返定格值） | clock_now |
| 0x699030 | 冻结（定格当前时刻） | clock_freeze |
| 0x699070 | ★ **换绑时间域（保持时刻连续）**【新发现】 | clock_bind_domain |

注意：0x698DC0/0x6989F0/0x698F80/0x6990D0 与时钟**无关**——它们是同一地址邻域的
ISocket/connect 实现（socket/setsockopt/WSAAsyncSelect 直证），勿混入本模块。

## 5. ★ 新发现：sub_699070 时钟换域（42 轮研究未记载）

`clock_bind_domain(clk, newDomain)`：先按旧域算 now，切 domainId 后重算 offset 使 now 连续。
冻结中换域则保持 frozenValue。语义：运行中的时钟可迁移到另一条时间域而不跳变。
用途推断：模块切换/演出时把对象挂到不同的域上【推断，读者调用点待追】。

## 6. 引擎消费者实例：CNMainGameModule::vmt4（0x444C60，帧 tick）

反编译直证的每帧流程（节选，完整重建归 P5 游戏对象层）：

1. `sub_4AEB30(&unk_9A02B0)` → `sub_433690()`（主帧循环：临界区/帧 delta/声音队列/网络 flush）
2. **模块时钟 this+92**：fade 状态(this+20)≠0 ⇒ 冻结；否则解冻（this+106 门）→
   `dt = (clock_now - this+120) × 0.001`（秒）→ `sub_655A90(dt)` 推进场景
3. **镜头震动用户设置**：`*(dword_8F8548 + 8)` ∈ {0,1,2,3} → `sub_424EA0(camera, 0.0/0.3/0.7/1.0)`
   —— 与研究第 27 轮"四档 0/30/70/100%"完全吻合（振幅系数语义首次直证）
4. **fade 状态机**（this+20，时钟 this+24，fade 值 this+60 镜像到 0x8F8528+2484）：
   - case 1 进场淡入：0→255 / 250ms（`sub_4049C0` lerp）；到 255 → `sub_475810`+`sub_4284C0`
     （进副本复位）+ 音效 40 + 状态=2 + 倒计时清零
   - case 3 退场淡出：255→0 / 250ms；到 0 → `sub_444B30(0)`
   - case 4：0→255 / 500ms（`sub_423A80`）→ `sub_41D300(1)`

## 2026-10-06 | 会话 4：全量批量转写 —— 方法论与教训

**方法论确立（两层还原体系）：**
1. L1 精修层（人工语义还原，130 函数）：语义命名 + 结构注释 + 研究交叉引用。
2. L2 转写层（脚本规范化转写，9451 函数）：反编译输出 → 可 grep 的源码树。
   两层加起来覆盖率 77.8%（9466/12172 唯一函数），10% 目标 7.78 倍达成。

**工程教训：**
1. **IDA 批处理防死循环**：`ea = f.end_ea` 对异常函数（end ≤ start）永不前进 →
   必须 `ea = max(f.end_ea, ea+16)`。此 bug 导致 monster/engine 两轮 dump 卡死。
2. **IDA 崩溃残留锁文件**：kill IDA 后 i64 旁残留 .id0/.id1/.nam → 后续会话报
   "Database initialization failed with error 4"。恢复 = 全删 ARAD_* 从母本重拷。
   教训：**绝不在 IDA 会话运行中 kill 进程**；正确姿势是等它自己 qexit。
3. **Hex-Rays 类型清洗的顺序陷阱**：`__int16`→`int16_t` 先于
   `unsigned __int16`→`uint16_t` 执行会产出 `unsigned int16_t` 残形。
   **长模式必须排在短模式前**。
4. **子代理额度风险**：4 个并行转写子代理全部因订阅额度耗尽失败；
   脚本化转写引擎（tools/transcribe.py）作为保底路线一次跑通。
   后续如需并行，先确认额度再派发。
5. **>8KB 巨型函数会卡死 Hex-Rays 批处理**：加 MAXSIZE 过滤 + SKIPPED-BIG 清单，
   巨型函数留给专项会话（现存：combat 1 / miscb 3 / skills 5 / uilogin 2 / monster 3 +
   核心区历史跳过若干）。

**新素材成果：**
- 9 个 dump 文件共 20.5MB / 9,451 函数反编译文本（work/dump_*.txt）。
- 21 个模块源码文件（src/game + src/combat + src/nengine 新文件）。
- 全库 VA 索引可 grep：`grep -rn "^// 0x" src/` 直达任何函数。

## 会话 12（2026-10-11）· 地图实现的重大修正（分辨率 / z序 / 按键体系）

**根因：内部渲染分辨率不是 800x600，而是 640x480。** 数据自证：

| 数值 | 与 640x480 的关系 |

| far1.img 内容 | 「远山+水面倒影」——**绝不能纵向平铺**（会重复山与倒影） |

### 14.1 补丁（同日）· 窗口全黑修复

### 2. 单位闭合（这是上一轮卡住的地方）

官方积分器 `CNRDParticle__vmt8`（`src/game/pvp_ui.cpp:6253`/`6319`）同时给出两式：

```c
pos[轴] = 基准[轴] - dword_7930D0[轴] * 速度[轴] * 0.01;   // 线性
z      += t * t * g / -2000000;                           // 二次（t 毫秒，g = -1500）
```

二次项 = `½·g·(t/1000)²` —— 正是「t 毫秒、g 以 px/s²」的精确自由落体式
⇒ 线性项的 `dword_7930D0[轴] × 0.01` 必须是**该轴已过时间（秒）**，
即 `dword_7930D0[轴]` = **该轴累计时间（百分秒）**（PVF 解密里初值 100 = 1 秒，旁证）。
⇒ **位置 px / 速度 px每秒 / 重力 px每秒方**，且官方是**解析积分**（`pos = 基准 + 速度 × 时间`）。

### 3. 跳跃：官方公式 + 官方重力 1500

// anim_parser.cpp:4724

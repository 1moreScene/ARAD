# custom-dnf 第一步 · 设计说明

> 范围：**可玩场景（官方真实素材）+ 默认鬼剑士 + 与官方一致的移动/奔跑/跳跃逻辑 + 官方默认键位**。
> 目标不是"做一个游戏"，而是把「坐标系 / 层次 / 时间 / 输入 / 弹道」这些**骨架**做成官方的形状，
> 并且**画面、地图、角色全部直接用官方文件**（`.map` / `.til` / `.NPK` / `.img` / `.ani` / `.chr`），
> 不自制替代素材。

---

## 1. 为什么是零依赖

* 官方客户端是 D3D8 + DirectInput8 的 2006 年技术栈；本步的画面是**纯 2D 精灵合成**
  （官方素材本身就是预渲染精灵 + 画布偏移），用不上着色器，**软件光栅 + GDI 呈现**完全够用，而且：
  * 离线可构建（不依赖 crates.io 网络）；
  * 逐像素可断言（无头 PNG 导出 → 确定性验证）；
  * 不会被 wgpu/winapi 版本漂移拖累。
* 唯一的外部依赖是系统 DLL：`user32`（窗口/输入）、`gdi32`（呈现）、`kernel32`（计时），
  全部手写 `#[link] extern "system"` 声明。

## 2. 坐标系：2.5D（照抄官方语义）

| 轴 | 含义 | 来源 |
|---|---|---|
| `x` | 水平轴 | 官方 `.map` 的对象锚点 x |
| `y` | **纵深轴**（进/出屏幕） | 官方 `.map` 的对象锚点 y；**直接就是屏幕 y**（`docs/90` 会话 13 第 5 条） |
| `z` | 跳跃的**屏幕上移量** | 不影响 `y`；只影响绘制偏移与影子大小 |

* **方向键语义**：`←/→` 动 `x`；`↑/↓` 动 `y`（纵深）。
* **画家排序**：按 `y` 从小到大绘制 ⇒ `y` 大的角色挡住 `y` 小的。
* **房间**：直接读官方 `map/lorien/104.map` —— 5 条瓦片带 × 224px = **1120px** 宽，
  左右门外沿 `x = 16 / 1104`；纵深由每条 `.til` 的 `[pass type]` 网格给出
  （14 列 × 30 行 × 16px，`0` = 可走、`2` = 阻挡；洛兰森林实测可走带 `y ≈ 224..463`）。
* **出生点** = `[pathgate pos]` 里最靠左的门（官方就是从左门进房），
  相机恒夹在 `[0, 房间宽-640]` 内，所以视口永远落在房间内、不露黑边。

## 3. 时间：固定步长 + 官方毫秒

* 逻辑按 **60Hz 定步**推进；真实耗时经 `FixedClock` 的余量累积器切成整数步
  （`crates/dnf-core/src/clock.rs`），所以逻辑步数与真实时间长期一致，且**完全可复现**。
* 动画时长直接用官方 `.ani` 的 `[DELAY]`（毫秒）。速率换算来自 `IRDActiveObject_vmt3D8`
  （0x495A10）：`sub_493D00(动画, a2 × 0.1)`，`a2` 由 `vt+888` 传入。
  自由态/跳跃态切入动作用的是 `vt+888(this, 1, 0|1, 1000, 1000)`
  ⇒ **动作播放速率 = 100%**（`1000 × 0.1`）。
  ⚠ 修正：`[move speed]` 的千分值**只缩放位移速率**（`vmt37C` 的 `× this_[1663] × 0.001`），
  **不缩放动画播放速率** —— 早期文档把两者混为一谈，已改。
* **官方「保持帧」语义**：`[DELAY] 10000` 表示「动画停在此帧等**物理**放行」。
  `jump.ani` 帧 7（顶点）/ 帧 14（落地前）就是这个写法；官方在 `z 速度 ≤ 0` 时用
  `sub_4AECE0(动画, 顶点帧)` **直接把帧设过去**（`char_server_info.cpp:4913-4920`），
  落地时再切落地帧。本工程用 `AnimPlayer::set_frame()` + `release_hold()` 复现同一时序。

## 4. 移动（参数全部来自官方状态机）

```
每轴速度参数（px/s，官方写死的数）
    走（sub_58E920 case 0）: x 直 143 / 斜 119      y 直 114 / 斜 95
    跑（equ_buff.cpp:7172）: x 直 286 / 斜 238      y 直 136 / 斜 114
    跳跃（正常）: 继承起跳时的地面档位（走 → 143/119·114/95；跑 → 286/238·136/114）
    跳跃（受控/技能，包标志 6988!=0）: x 286/286、y 0（空中不能调纵深、不能改朝向）
档位选择 = 任一轴「无输入」→ 直向档，否则斜向档     （IRDActiveObject_vmt36C）
速率     = 参数 × 朝向符号(0/2→-1, 1/3→+1, 4→0) × ([move speed] / 1000)   （vmt37C）
积分     = pos = 基准 + 速率 × 该轴累计时间          （官方解析式；本工程取整 + 余量）
```

⚠ **走与跑的纵深比不同**：走 `114/143 = 0.797`，跑 `136/286 = 0.476` ⇒ 各用各的官方数。

鬼剑士实测（`[move speed] 850` → 倍率 0.85）：

| 动作 | x px/s | y px/s |
|---|---|---|
| 走（单轴输入） | **121.55** | 96.90 |
| 走（斜向两轴） | **101.15** | 80.75 |
| 跑（单轴输入） | **243.10** | 115.60 |
| 跑（斜向两轴） | **202.30** | 96.90 |
| 跳跃（空中，走起跳） | 121.55 | 96.90 |
| 跳跃（空中，跑起跳） | 243.10 | 115.60 |

* **方向输入（官方语义：后按的键优先）**：每轴一个「按下顺序栈」，栈顶即当前方向；
  松开后**自动回落到仍按住的另一个键**（官方 `sub_4BF3D0` 从尾向前取最近一条有效记录，
  见 [02_移动与跳跃取证.md](02_移动与跳跃取证.md) §1.10）—— 不是「两键相抵 = 停住」。
* **8 方向**：两轴独立 ⇒ 可同时前进+纵深；**斜向不做 cos45° 归一化**
  —— 官方给的是另一组数（119/95），合成模长 152.3 比直向 143 大 6.5%，这是官方手感。
  纵深比横轴慢正是官方的 `114/143 = 95/119 ≈ 0.797`。
* **跑（286/136 档）**：**双击方向键**触发；单击/按住只走 143/114 档；
  **进入奔跑后切换方向仍然是奔跑**（官方奔跑状态在服务端持有，客户端只换方向符号）。
  双击要求该轴**回到中立**（官方输入容器的记录模型：一次点击须上一个记录已失效）
  ⇒ 按住 ← 猛按 → **不触发**奔跑；转向后奔跑结束（需重新双击）。
  双击窗口 15 步 ≈ 250ms 是本工程**唯一**的标定值（官方触发在未还原的输入层）。
* **空中（正常跳跃）**：**继承起跳时的地面档位、两轴都能动** —— 官方跳跃分支把
  `+1719..1722` 的暂存参数写回 x 轴、且**不写 y 轴**（见 [02](02_移动与跳跃取证.md) §1.7）
  ⇒ 走起跳是 143/119 + 114/95，跑起跳是 286/238 + 136/114，
  **可以调整落地点（含 ↑↓ 纵深）**，也可以改朝向（`case 6` 的 `vt+148/vt+144`）。
* **朝向**：水平分量决定，`x` 分量为 0 时保持原朝向（官方「方向值 4」= 速率为 0）。

## 5. 跳跃（官方公式 + 官方重力，无标定值）

官方起跳（`src/game/ui/char_server_info.cpp:4254-4290`）：

```c
v119 = sub_495430(v66, sub_4B0D20(属性块), sub_495580(属性块));
sub_494F20(2, v119);          // 写 z 轴速度
```

```c
// src/game/anim_parser.cpp:4724
double sub_495430(int a1, int a2, int a3)
{ return (double)(4000 * a1) / ((double)(100 * a2 / a3 - 10000) * 0.0121 + 2100.0); }
```

三个入参的官方字段（偏移映射见 [02_移动与跳跃取证.md](02_移动与跳跃取证.md) §1.7）：

* `a1` = **`[jump power]`**（官方样例注释：1000 = 标准值；技能的同一参数来自 `.skl [static data]`，
  官方后跳技能 = 200）；
* `a2` = **`[weight]`**（属性块 `+984`；官方样例注释「单位 10g」）—— 越重跳越低；
* `a3` = **`[jump speed]`**（属性块 `+956`）—— 它**同时缩放重力**。

重力（`sub_4957F0`）：**`g = 1500 × [jump speed]/100`** px/s²（自由态入场选「属性加权」模式 2）。
鬼剑士 `[jump speed] 95` ⇒ **1425 px/s²**（跳速越低越飘）。

**积分是解析式**（`pos = 基准 + 速度 × 该轴累计时间`、`z += ½·g·(t/1000)²`，`pvp_ui.cpp:6319`）
⇒ 顶点/落地时刻与帧率无关。

鬼剑士（`[jump power] 430 / [weight] 68000 / [jump speed] 95`）：

| 量 | 值 |
|---|---|
| 初速度 | **604.6 px/s** |
| 最高点 | **128.3 px**（≈ 角色高度 1.3 倍） |
| 上升 / 滞空 | **424 ms / 849 ms** |
| 水平 | 起跳用 286 档 ⇒ 一跳约 206 px |

**顶点与落地由物理驱动，不是由动画时长决定**（`sub_58FC30` 的 `case 6`，`:4898-4930`）：

* `z 速度 ≤ 0` ⇒ 把动画**直接设到** `jump.ani` 的顶点保持帧（下标 7，`[DELAY] 10000`）；
* 下落中且贴地 ⇒ 落地：切到落地保持帧（下标 14）→ 播帧 15（50ms）→ 回站立；
* **正常跳跃继承起跳时的地面档位（两轴）** ⇒ 空中可调纵深落点、可改朝向；
  只有受控/技能跳跃（包标志 `6988 != 0`）才把轴 1 写 0；
* 击飞常量（`:4203-4205`）：`x = ±200`、`z = 400`；重型击飞（`:3939-3942`）`x = z / 2`。

## 6. 渲染（官方真实素材）

* 逻辑分辨率 **640×480**（官方内部渲染分辨率）。
* 每一帧按官方层次顺序拼出来（`crates/dnf-app/src/room.rs`）：

  ```
  远景层(distantback, 视差 56%) → 中景层(middleback, 视差 90%) → 瓦片条(世界锁定)
    → closeback 物件 → bottom 物件 → normal 物件(按锚点 y 排序) → 角色 → close 物件(前景)
  ```

  * 远景/中景：`.map` 的 `[background animation]` → `.ani` → `Map\01far1.img`（640×295），
    横向按 640 取模平铺，位移 = `camera_x × 视差率 / 100`。
  * 瓦片条：`.til` 的 `[IMAGE]` → `Map\01tile00.img`（画布 224×480，美术贴画布 `(0, 277)`），
    屏幕 x = `条号 × 224 - camera_x`。
  * 物件：`.map` 的 `[animation]` → `.ani` → `.img`，锚点 = 官方坐标，
    绘制偏移 = `[IMAGE POS] + 帧在画布内的 (x, y)`。
* 角色是**官方分层合成**，绘制顺序 = 官方 `.equ` 的 **`[LAYER]` 升序**（身体层 0）：
  身体层读 `character/swordman/animation/<动作>.ani`（权威帧序 + `[IMAGE POS]`）；
  每个时装槽按 `[equipment type]` + `[variation]` 在官方表里定位装备
  （`equipment/character/swordman/avatar/<槽>/<物品>.equ`），取它的 `[LAYER]` 与部件目录
  `equipment/.../avatar/<槽>/<槽>_<字母>/<动作>.ani` 里的**路径模板** `sm_coat%02d%02da.img`，
  用 `[variation]` 填号。
  官方层值（剑士）：`face_b 100` / `coat_d 500` / `neck_d 600` / `belt_b 1100` / `shoes_b 1200` /
  `pants_b 1300` / `shoes_a 1400` / `pants_a 1500` / `belt_a 1700` / `neck_a 1800` /
  `coat_a 1900` / `hair_a 2000` / `cap_a 2100` / `neck_c 2200` / `cap_c 2500`（负数 = 画在身体之前）。
  身体层 = 0 是**区间推断**（负数层＝身体之前、最小正数层＝99/100 ⇒ 身体 ∈ `(-50,99)`）。
  同一槽的**兄弟部件一起画**（`.equ` 只点一个目录，但裤子真正的美术在 `pants_b`）。
  官方图集里还有"什么都不画"的**空帧**（1x1 全透明、画布 `(500,0)`），并大量使用
  `tag 0x11` **别名帧**（`sm_pants0000a.img` 188 帧里 182 帧是别名）——两者都已正确解析。
* TODO：本步把 `.img` 的两类帧都实现了（16 位 A1R5G5B5 与别名帧 `tag 0x11`），
  但**8 位调色板帧**尚未在真实文件上遇到，遇到会直接报错而不是猜。
* **转向 = 镜像**：官方靠动画速率取负（`IRDActiveObject_vmt37C`），等价于**以角色脚点为轴
  水平翻转整块画布** ⇒ 每层左边缘 = `角色屏幕x − (偏移 + 精灵宽) + 1`（未翻转时 = `x + 偏移`）。
  实现见 `game.rs::layer_screen_pos`，逐像素回归测试见 `game.rs::左右朝向互为镜像_站立与行走`。
* 影子：脚下椭圆，随跳跃高度缩小变淡（高度来自弹道，见 §5）。
* HUD：5×7 点阵字体（自绘，无字库依赖），显示动作状态 / 坐标 / 高度 / 帧号。

## 7. 确定性回放（无头模式）

`--headless` 用一条**纯函数式**输入时间线（`crates/dnf-app/src/script.rs`）驱动角色：
**同一步号 ⇒ 同一输入 ⇒ 同一画面**。因此可以：

* 导出关键帧 PNG（动作切换点 / 跳跃最高点 / 起跳 / 落地）供目视验证；
* 打印逐帧轨迹（`--trace`）核对帧序、坐标、高度；
* 在测试里断言帧序单调、「保持帧被放行」、落地帧必须播到等官方语义。

## 1. 已确证（有官方代码或官方文件）

### 1.1 速度倍率 = `[move speed] / 1000`

* 官方数据注释：`sample/charactersample.chr` → `[move speed] 1000  // 1000이 표시상 100%`
* 官方代码：`IRDActiveObject_vmt3D0`（`src/cnrd/IRDActiveObject.cpp:205` 附近，0x495740）

  ```c
  //   1 = 移动速度: 属性块(vt+672(3)) +816 防篡读 × +830 浮点系数
  //   default = 1000（千分基准）
  case 1: {
      int v2 = (*(...)(*(int*)this_ + 672))(this_, 3);
      int v3 = sub_41A5E0(v2 + 816);
      return (int)((double)v3 * COERCE_FLOAT(sub_41A5E0(v2 + 830)));
  }
  ```

  ⇒ 移动速度是**千分值**（1000 = 100%）。鬼剑士 `swordman.chr` 实测 `850`。

### 1.2 千分值 → 动画播放速率（×0.1）

* `IRDActiveObject_vmt3D8`（0x495A10，`src/cnrd/IRDActiveObject.cpp`）

  ```c
  float v6 = (double)a2 * 0.1;     // 千分 → 百分
  sub_493D00((void*)v3, v6);       // 写动画速率（并传染 +128 子对象链）
  ```

  ⇒ 上帝视角看：**角色位移是靠动画速率体现的**（850 → 动画 85%），
  所以本工程把「每步位移 ∝ 速率」作为模型（速率 = 850/1000）。

### 1.3 朝向是 4 档，镜像靠**速率取负**

* `IRDActiveObject_vmt37C`（0x495600，`src/cnrd/IRDActiveObject.cpp`）

  ```c
  if (a3 == 0 || a3 == 2) v12 = -1.0f;

  ```

* 另一处同源判定：`src/game/anim_parser.cpp:5451`

  ```c
  if ( COERCE_FLOAT(sub_41A5E0(this + 976)) < 0.0 ) sub_41A590(0);   // 负速率 = 反向
  ```

  ⇒ 本工程的 ±1 + flip 是它的等价折叠（见 `dnf-core/src/movement.rs::facing_from_dir`）。

### 1.4 每帧位移的官方式子 + **单位（已闭合）**

* `src/game/pvp_ui.cpp:6253` / `:6319`（`CNRDParticle__vmt8` 物理更新，注释标为「P36⑤ 全公式」）：

  ```c
  // 位移（线性）
  *(this + j + 34) = *(this + j + 1) - (uint64_t)((double)dword_7930D0[j] * *(&v17 + j) * -0.0099999998);
  // 自由落体（二次）
  v11 = *(this + 33);  v13 = v11 * v11 * *(this + 18) / -2000000;  *(this + 36) = v13 + v12;
  ```

* 同 `src/game/anim_parser.cpp:378`：`v6[i] += (int)(dword_7930D0[i] * 速度) / 100;`

**单位推导（三条互相印证，结论：位置 = px、速度 = px/s、重力 = px/s²）**

1. 二次项 `t² · g / (−2000000)`，其中 `t` 是该对象时钟的**毫秒**、`g = −1500`
   ⇒ 等价于 `½ · g · (t/1000)²` —— **正是「t 毫秒、g 以 px/s²」时的精确自由落体式**
   （`−2e6 = −2 × 1000²`）。
2. 于是线性项里的 `dword_7930D0[轴] × 0.01` 必须是「该轴已经过的时间（秒）」
   ⇒ **`dword_7930D0[轴]` = 该轴运动累计时间（百分秒，整数）**。
   PVF 解密里该基址初值 `100`（= 1 秒）与此吻合（弱证据，仅作旁证）。
3. 官方活动对象的位置/速度字段：`controller+4/+8/+12` = 位置（int，px）、
   `controller+16/+20/+24` = 速度（float）、`controller+28/+32/+36` = 第二组（int，其中
   **`+36` = 重力**，见 §1.7）、`+192` = 落地类型、`+196` = 脏标记
   （写入点：`sub_494F20`、`IRDActiveObject_vmt37C`、`sub_495890`；读取点：
   `bigfunc_5E78C0_sub_5E78C0.cpp:517` 的 `fabs(*(float *)(*(a1+112)+16)) >= 50.0` 等）。

* 官方是**解析积分**（`pos = 基准 + 速度 × 该轴累计时间`），不是逐步欧拉累加 ——
  所以官方代码在 16.7ms 步长下也不会过冲。本工程照此实现（[`jump::Jump::step`] 用解析式，
  走/跑用浮点余量累积，见 `dnf-core/src/movement.rs`、`jump.rs`）。

### 1.5 官方速度参数表（这组数是官方的，不是拟合的）

官方自由行动态进入时写死每轴参数（`src/game/ui/char_server_info.cpp:3772-3773`）：

```c
(vt+876)(this, 0, 143, 119, 1, 0, 0);   // 轴 0（x）：直向 143 / 斜向 119
(vt+876)(this, 1, 114,  95, 1, 0, 0);   // 轴 1（y）：直向 114 / 斜向  95
```

**奔跑（冲刺）有自己的一组官方参数**（`src/game/equ_buff.cpp:7172`，并由 `:7290-7293`
存进 `+1719..1722` 供落地后恢复）：

```c
(vt+876)(this, 0, 286, 238, 1, 0, 0);   // 轴 0：直向 286 / 斜向 238
// 同一组存进暂存字段（+1719..1722 = x直, x斜, y直, y斜）：
*(this + 1719) = 286;  *(this + 1720) = 238;
*(this + 1721) = 136;  *(this + 1722) = 114;   // 轴 1：直向 136 / 斜向 114
```

跳跃的空中水平参数是 `(vt+876)(this, 0, 286, 286, 0, 0)`（`char_server_info.cpp:4270`）
⇒ 两个档位都写 286、**空中不做直向/斜向区分**。但请注意：这只是**受控/技能跳跃**那一支；
正常玩家跳跃走 `6988 == 0` 的分支（见 §1.7 末段），它用的是**暂存的地面参数**。

⚠ **奔跑的纵深比与行走不同**：行走 `114/143 = 95/119 ≈ 0.797`，奔跑 `136/286 = 114/238 ≈ 0.476`
⇒ 纵深不能用一个比例推，必须各用各的官方数（本工程已按此实现）。

* 语义（`IRDActiveObject_vmt36C`，`src/cnrd/IRDActiveObject.cpp:295`）：
  `a3` → +6608 族「直向档」，`a4` → +6616 族「斜向档」；**任一轴无输入（方向值 4）就退回直向档**
  （`if (this_[1659] == 4 || this_[1660] == 4) flag = 0;`）。
* 合成（`IRDActiveObject_vmt37C`，同文件 `:253`）：
  `速率 = 档位值 × 朝向符号 × (this_[1663] × 0.001)`，其中
  **朝向 0/2 → −1（左）、1/3 → +1（右）、4（无输入）→ 0（速率为 0）**；
  `this_[1663]` = `vmt3D0(this, 1)` = `[move speed]` 千分值。
* ⇒ 鬼剑士（`[move speed] 850`）实测：
  **走 143×0.85 = 121.55 px/s**（y 96.90）、**斜向 119×0.85 = 101.15 / 95×0.85 = 80.75**、
  **冲刺 286×0.85 = 243.10**（y 136×0.85 = 115.60；斜向 238×0.85 = 202.30 / 114×0.85 = 96.90）。
  `--info` 会把这些数全打出来。
* 斜向**不是** cos45° 归一化：官方另给一组数（119/95），两轴合成模长 152.3 > 直向 143（大 6.5%）。
  纵深比横轴慢正是 `114/143 = 95/119 ≈ 0.797`。

### 1.6 动画播放速率 = 100%（`[move speed]` 只缩放位移）

`vmt378`（`IRDActiveObject.cpp:181`）把两个参数分别送到
`vt+980`（`vmt3D4` → 写 `+6652` = **移动千分档**）与
`vt+984`（`vmt3D8` → `sub_493D00(动画, a × 0.1)` = **动画速率**）。
自由态/跳跃态切入动作调用的是 `vt+888(this, 1, 0|1, 1000, 1000)`
⇒ **移动千分档 = `[move speed]`（850），动画速率 = 1000 × 0.1 = 100.0 = 100%**。

⇒ 本工程此前把「移速千分值 × 0.1」当动画速率是**错的**，现已修正：
`[move speed]` 只缩放**位移速率**，动作播放速率恒为 100%（`actor::OFFICIAL_CLIP_RATE`）。

**空中规则（跳跃继承地面档位）** —— 起跳分支有**两条路**，由包载荷第 4 字节决定
（`:4222` 的 `*(this + 6988) = 包[4] != 0`）：

### 1.10 方向输入：**后按的键优先**（同轴反向键不是「停住」）

官方把方向拆成**两个独立的轴**，每轴一个输入容器：

* `src/game/equ_buff.cpp:331-333`：x 轴用 `unk_9A0310`、y 轴用 `unk_9A0320`；
* 取方向用 `sub_4BF3D0`（`src/game/equ_buff.cpp:13056`）：

  ```c
  for (i = 最后一条记录; ; i -= 16) {          // ★ 从尾向前扫
      if (*(uint8_t *)(i + 12) != 0              // 该记录仍有效（键还按着）
       && 记录 id ∈ 允许集) { 命中 = i; break; }
      if (--v4 < 0) return -1;                    // 全无效 → 无输入
  }
  return *(uint32_t *)命中;                       // ⇒ 取**最近**按下且仍按住的那个
  ```

  ⇒ **后按的键覆盖先按的**；松开某键时它的记录被置无效（`sub_4BF450`），
  于是**自动回落到仍按住的另一个键**（按住 ← 再按 → ⇒ 向右；松开 → ⇒ 又向左）。
  只有**两键都松开**才出现「无输入」。
* 键盘设备对外提供的就是**上升沿查询**（`sub_415200`，`src/nengine/gfx_texture.cpp:5013`：
  `当前帧按下 && 上一帧未按下`），说明「哪个键刚按下」在官方是被追踪的状态；
* `sub_4B04B0`（`src/game/equ_buff.cpp:325`）把该值映射成 `0..3` 的方向码，
  `4` = 无输入，供状态机与 `vmt37C` 使用；两轴独立 ⇒ 斜向（官方斜向另给参数档 119/95）；
* 另一个相关函数是 `sub_495010`（`src/game/anim_parser.cpp:4459`）：
  当**只有单轴有输入**时，它会用碰撞查询（`vt+136`）沿 4 槽方向环试探**相邻方向**，
  找到可达的方向 —— 即官方的「贴墙自动微调方向」。

> 本工程此前用「两键相抵 → 停住」，与官方不符；现已按上述语义实现
> （[`crate::input::AxisInput`]：按下顺序栈，栈顶优先、松开自动回落），并有单测
> `方向_后按的键优先_松开后回落`。

**双击（奔跑）判定同样建立在这个「记录」模型上**：官方容器里一条记录要算「一次点击」，
前提是**上一个记录已经失效**（该键已松开、且该轴没有别的键按着）——
因此「按住 ← 同时猛按 →」**永远不构成双击**，不会进入奔跑；

* 奔跑触发方式：官方命令表（`skill/rdarkeyindex.dat` → `(UP)…(BUFF)`）里**没有**「跑步/冲刺」命令
  ⇒ 只能是**双击方向键**这一手势（本工程唯一保留的标定值 = 双击窗口 15 步 ≈ 250ms）；
* 官方奔跑是**服务端状态 11**（`equ_buff.cpp:7035` 的 `v49 = *(this+1639)` 与 `:7288` 的
  `v49 == 11` 判定；其处理器 `sub_4B89D0` = 「跑步地面循环」，`equ_buff.cpp:6982`）；
* **奔跑中切换方向仍然是奔跑**：状态 11 由服务端持有，客户端只按当前方向重算速率符号
